# Первый технический срез: один проверяемый пакет

**Статус:** контракт технического эксперимента, дальнейшее развитие которого остановлено по уточнению владельца. Обычный путь теперь задаёт [быстрый обзор и уровни глубины](../product/analysis-depth.md). Отдельная локальная реализация и проверка трёх кадров существуют, но её незавершённые исправления сохранены без публикации; готовой продуктовой функцией этот эксперимент не считается.

## Граница и решение

Один явно выбранный локальный видеофайл → SHA-256 и FFprobe → три кадра → `manifest.json` → ручная сверка. Это контроль временной точности, а не обязательный этап обычного обзора библиотеки. Звук, речь, поиск, сервер и интерфейс сюда не входят. Возвращение к PNG требует отдельной задачи; текущий путь указан в [`roadmap.md`](../roadmap.md).

Хранение: один каталог пакета с `manifest.json` и `frames/`. JSON читается человеком, проверяется без сервиса и достаточен для одного файла. SQLite имеет смысл при множестве материалов, транзакционных обновлениях или запросах; такой потребности пока нет. Серверная БД и web framework не нужны.

Владелец контракта — архитектор ядра; способ получения кадра и его PTS проверяет инженер медиа. Если связь изображения с PTS или длительность не подтверждаются, движение к анализу останавливается до отдельной проверки.

## Вход и выборка

- Вход: путь к одному существующему обычному файлу, переданный явно; выход: отдельный локальный каталог. Ни обхода папок, ни URL, ни сетевого источника.
- Сначала считать SHA-256 и размер; FFprobe определить формат, один выбранный видеопоток, кодек, размеры, рациональный `time_base` и положительную длительность видеопотока как **подсказку для выборки**. Метаданные длительности не доказывают время конкретного кадра.
- Нулевая точка пользовательского отсчёта — PTS первого предъявленного кадра выбранного потока. Запросить позиции 0%, 50% и 90% от подсказки длительности относительно этой точки. Правило выбора кадра: первый предъявленный кадр с исходным временем не раньше запрошенной позиции. Ускорение через seek допустимо лишь при доказанной той же связи кадра и PTS.
- Требуются три отдельные записи кадров с разными исходными PTS в возрастающем порядке; сами изображения могут быть одинаковыми. Если поток слишком короток, повреждён или подсказка длительности не позволяет это сделать, вернуть явную ошибку. Не дорисовывать «недостающие» кадры и не ставить им ожидаемые времена.

## Минимальный manifest

```json
{
  "schema_version": 1,
  "source": {"sha256": "…", "bytes": 12345, "format_name": "…"},
  "tools": {"ffprobe": "…", "ffmpeg": "…"},
  "video": {
    "stream_index": 0, "codec": "…", "width": 1920, "height": 1080,
    "time_base": "1/90000", "first_pts": 900000,
    "duration_hint_seconds": "10.0"
  },
  "recipe": {"id": "three-samples-v1", "target_fractions": ["0", "0.5", "0.9"]},
  "frames": [
    {"file": "frames/0001.png", "sha256": "…",
     "requested_offset_seconds": "0", "source_pts": 900000,
     "timestamp_basis": "best_effort_timestamp"},
    {"file": "frames/0002.png", "sha256": "…",
     "requested_offset_seconds": "5", "source_pts": 1350000,
     "timestamp_basis": "best_effort_timestamp"},
    {"file": "frames/0003.png", "sha256": "…",
     "requested_offset_seconds": "9", "source_pts": 1710000,
     "timestamp_basis": "best_effort_timestamp"}
  ]
}
```

В действительном пакете `frames` содержит ровно три записи; многоточия здесь — только места для реальных значений. Пути внутри пакета относительные; исходный путь, полные FFprobe tags и личное имя файла в manifest не попадают. `tools` и `recipe` нужны для повторяемости, хеш каждого PNG — для проверки неизменности. Числа времени хранить как целые PTS и рациональный `time_base` либо десятичные строки, без округления до кадровой частоты.

`requested_offset_seconds` — цель выборки. `source_pts` — метка предъявления **того же декодированного кадра**, из которого сохранён PNG, в `video.time_base`. Его позиция от начала равна `(source_pts - first_pts) × time_base`; значение для показа можно округлить, исходные числа — нельзя. Если декодер даёт лишь вычисленную метку предъявления, способ её получения надо точно назвать в `timestamp_basis`; отсутствие надёжной метки — ошибка пакета. Выходной PNG, имя файла и само по себе время `-ss` не доказывают исходный PTS. [FFmpeg описывает ограничения seek](https://ffmpeg.org/ffmpeg.html#Main-options), [FFprobe — поля кадров](https://ffmpeg.org/ffprobe.html#Main-options).

Инварианты: один SHA-256 входных байтов для всего пакета; один выбранный поток и его `time_base`; каждый PNG связан с конкретным декодированным кадром; PTS и ссылки на файлы уникальны; все файлы и их хеши существуют; относительные пути не выходят из каталога пакета. Нельзя подставлять кадр из соседнего seek или менять начальную точку молча. При разрывах или неоднозначности временной шкалы первый срез сообщает неподдерживаемый вход, без выдуманной гарантии точности.

## Ошибки, запись и повтор

Отдельно сообщать: файл не читается или меняется во время работы; нет видеопотока либо нужной длительности; поток/кодек не декодируется; нет трёх разных кадров с PTS; сбой FFprobe/FFmpeg; недостаток места; неполная запись или несоответствие хеша. После подготовки пересчитать SHA-256 источника: различие с первым хешем отменяет пакет. Равенство хешей не является абсолютной защитой от внешней записи между проверками.

Собирать пакет во временном каталоге **внутри того же корня вывода**. Перед публикацией проверить JSON, файлы, хеши и связь меток; затем переименовать готовый каталог в конечное имя, включающее хеш источника и отпечаток рецепта/версий инструментов. Не перезаписывать существующий пакет. При повторе проверить его manifest и файлы: совпали — использовать; повреждены или отличаются — сообщить ошибку. Прерванная сборка остаётся непубличной; удалять только собственный опознанный временный каталог. Переименование описывает видимость результата на обычном локальном файловом томе, не обещает сохранности при сбое питания или для произвольного сетевого диска.

## Доступ и приёмка

Подготовка читает только явно выбранный исходник и пишет только в выбранный вывод; запуск внешних программ — аргументами без shell. Запрет сетевого доступа и права только на чтение требуют ограничения процесса средствами ОС, а не текста `AGENTS.md`. Текущий инженерный сеанс такой изоляцией не считается. Будущий аналитический процесс должен получать лишь готовый пакет с технически ограниченными правами; путь к исходнику и авторизацию Codex ему не передавать. Никаких скрытых платных API и внешних VLM.

При отдельно назначенном возвращении к этому эксперименту контракт проверяется на синтетическом видео в CI. Личный материал автор выбирает для локальной проверки вне репозитория: открыть все три PNG, сопоставить каждый с оригиналом по записанному PTS, проверить расхождение цели и факта, повторный запуск и понятную ошибку на испорченном входе. Пока человек не открыл кадры, запись пути к ним не считается просмотром. Результат ручной проверки фиксируется отдельно от неизменяемого пакета; заранее ставить отметку «проверено» нельзя.
