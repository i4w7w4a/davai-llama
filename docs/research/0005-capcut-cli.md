# CapCut: локальный CLI и официальная Web-интеграция

29 сентября 2026. **CapCut выбран владельцем. Для локального Desktop проверяем `capcut-cli`; его совместимость с установленным CapCut 9.4.0.4015 пока не доказана.** Найден также официальный CapCut × Codex, но его опубликованный контракт работает с облачным Web-черновиком. Это два разных маршрута, выбирать между ними по одному названию MCP нельзя.

Проверка статическая: документация, исходники и содержимое официального архива. Ничего не устанавливалось и не запускалось; личные проекты не читались. Локально прочитаны только метаданные установленного исполняемого файла и версия Node (`24.13.0`). Полный внешний отчёт владельца сохранён приватно. Его рекомендация другого редактора не отменяет прямой выбор CapCut.

## Что добавилось к внешнему исследованию

В отчёте разбирался другой проект — `bchenner/capcut-mcp`; `renezander030/capcut-cli` отсутствует. Общий вывод об отсутствии поддерживаемого пути надо уточнить: [официальная страница CapCut × Codex](https://www.capcut.com/tools/capcut-x-codex) заявляет совместную работу с таймлайном, но проверенный пакет ведёт в Web. Наличие общего официального Desktop API этим не подтверждается. Ссылки `turn…` в переданном отчёте не заменяют доступных первоисточников; здесь используем новые прямые ссылки.

| Путь | Что подтверждено чтением | Что ещё проверить |
|---|---|---|
| `capcut-cli` 0.26.0 | Чтение и правка локальных JSON-проектов; предусмотрены Windows-пути | Что именно читает и сохраняет CapCut 9.4, видимость ручных правок, повторное открытие |
| Экспериментальный MCP внутри `capcut-cli` | Только `inspect`, `diff`, `lint-portable` в WASM | Это не интерфейс записи монтажного проекта |
| Официальный CapCut × Codex 0.2.0 | Удалённый MCP, управляемая сессия Web-черновика, чтение и отправка версии | Доступность аккаунта, реальная работа с ручными правками, передача в Desktop |

## `capcut-cli`: подтверждённые возможности и границы

Зафиксирован коммит [`a21cc9ce65ef169920f0e18cb130777a13bee838`](https://github.com/renezander030/capcut-cli/commit/a21cc9ce65ef169920f0e18cb130777a13bee838) от 28 сентября 2026. [Пакет](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/package.json) объявляет версию 0.26.0, Node ≥18 и MIT; [лицензия](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/LICENSE) проверена отдельно. На [странице автора](https://renezander.com/projects/capcut-cli/) ещё указана 0.22.0. Это независимый от CapCut проект.

В [справочнике команд](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/docs/command-reference.md) есть чтение дорожек, сегментов, текста, версии и диагностики; изменение текста, границ, скорости, громкости, добавление клипов и субтитров. Основная работа идёт через CLI/библиотеку. [WASM/MCP](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/wasm/capcut-core/README.md) ограничен чтением. Для первого локального опыта отдельная MCP-обёртка не обязательна — это наш инженерный вывод, а не уже созданная интеграция.

Главные ограничения:

1. **9.4 не проверена.** [Матрица версий](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/docs/version-support.md#L18-L29) относит прочие 9.x к непроверенным. По [коду реестра и защиты записи](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/version.ts) отсутствие запрета записи не означает проверенной совместимости. Локальная версия — основание для отдельного опыта, а не переноса чужой приёмки.
2. **Источник текущего состояния может различаться.** Обычное чтение выбирает один из корневых файлов, для новых форматов предпочитая `template-2.tmp`. Наличие вложенных `Timelines/` обнаруживается, но обычное редактирование не обслуживает их как канонический документ. См. [выбор корневого файла](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/store.ts#L392-L446) и [границу вложенных документов](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/store.ts#L29-L54). Сначала устанавливаем, где приложение действительно сохранило ручное изменение.
3. **Защита записи полезна, но не полна.** Есть проверка запущенного редактора для управляемых путей, сравнение текущих байтов с прочитанными, замена через временные файлы, backup и история. Уже существующее расхождение корневых копий само по себе не запрещает обычное сохранение; выбранная версия может распространиться на остальные. [Проверки](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/draft.ts#L274-L342), [сохранение](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/draft.ts#L363-L415). Не объявляем несколько файлов одной безусловно атомарной транзакцией.
4. **Откат и сравнение имеют ограниченный смысл.** `diff` сравнивает выбранные поля, а `restore` заменяет файл из backup без проверки последующих ручных изменений. См. [diff](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/index.ts#L5309-L5358), [restore](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/index.ts#L4848-L4892). Нашу приёмку сохранности проекта они целиком не заменяют.
5. **Экспорт не подтверждается постановкой в очередь.** `render` делает FFmpeg-превью; Windows-путь `export --batch` открывает проект и отправляет `Ctrl+E`. Это не подтверждённый финальный файл. См. [код экспорта](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/export-batch.ts#L124-L159).

В просмотренных setup-сценариях не найдено патча CapCut.exe или обхода шифрования. При этом [хук Claude-плагина](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/hooks/hooks.json) запускает глобальную установку, а [translate](https://github.com/renezander030/capcut-cli/blob/a21cc9ce65ef169920f0e18cb130777a13bee838/src/translate.ts#L90-L117) отправляет текст внешнему API. Поэтому целиком активировать чужой агентский набор для чтения черновика не требуется. Эти действия не выполнялись. Указания `decrypt` о вмешательстве в обновлятор другого продукта не являются частью нашего плана.

## Официальный CapCut × Codex

Прочитаны [установочный SKILL](https://sf16-sg.tiktokcdn.com/obj/eden-sg/962370eh7nupenuhbo/capcut_codex_plugin/SKILL.md) и [пакет plugins_v20.zip](https://sf16-sg.tiktokcdn.com/obj/eden-sg/962370eh7nupenuhbo/capcut_codex_plugin/plugins_v20.zip), версия 0.2.0. Размер прочитанного архива — 164 304 байта, SHA-256 `1dcb898ab582c070b4a7c75a410031e0e0d7a3ace640991e49de3d6d7272a7af`. URL изменяемый; хеш фиксирует именно исследованный экземпляр.

В `.mcp.json` — удалённый `capcut_creation` с OAuth и отдельный сервер ресурсов. `skills/web-collaborative-editing/SKILL.md` описывает управляемую облачную сессию: свежий снимок после ручного сохранения и отправку следующей версии с проверкой конфликта. Произвольная ссылка на прежний Web-проект не заменяет идентификатор такой сессии. Локальный Desktop-проект этим контрактом не обслуживается.

В `skills/video-editing/references/post-editing.md` указано, что результат AI-монтажа иногда переносится в Web как один готовый клип. Отдельные исходные склейки в таком результате не восстанавливаются; полноту редактируемости проверяем на фактическом черновике. Обратная передача Web-правок в AI-монтаж автоматически не гарантируется.

Для этого маршрута нужны подключение, авторизация и передача используемых медиа сервису. Работоспособность аккаунта, действующие схемы инструментов и переход между Web и Desktop не проверены. Он остаётся отдельно обозначенным вариантом; личная библиотека туда не загружалась. Официальная страница не служит доказательством доступности в текущем сеансе.

## Один следующий опыт

**Локальный путь, отдельный синтетический проект в CapCut 9.4.** Его задача — проверить обмен правками, не весь монтажный конвейер. Запланировано в [задаче №8](https://github.com/i4w7w4a/davai-llama/issues/8); выполнение ещё не начато.

1. В редакторе создать простой тестовый проект с титром, сохранить, вручную изменить титр, сохранить и закрыть редактор. Сделать отдельную полную копию тестового проекта и относящегося к нему индекса.
2. В изолированном окружении с закреплённым кодом прочитать `diagnose`, `version`, `texts`. `texts` должен показать точную ручную правку из шага 1; записать выбранный CLI корневой файл и состояние `Timelines/`. Диагностика показывает выбор CLI, но сама не доказывает, какой документ использует приложение. Не использовать `--force-write`, `sync-timelines --apply`, миграции и автопочинку, чтобы скрыть несовместимость.
3. Если состояние понятно и согласовано, изменить текст одного титра. Открыть результат в CapCut, сохранить, вручную изменить положение или временную границу титра и снова закрыть.
4. Прочитать новые значения агентом, затем выполнить ещё одну небольшую запись CLI — например, снова изменить только текст. Повторно открыть в CapCut и подтвердить, что ручное положение/временная граница сохранились. Проверить неизменность остальных интервалов/материалов и возможность восстановления отдельной копии.

Отказ на этом шаге: CLI не видит последнюю ручную правку, приложение игнорирует результат, источник в `Timelines/` не обслуживается или файлы расходятся. Тогда сохраняем свидетельства и ищем решение конкретного дефекта; не перезаписываем проект силой. Прохождение открывает путь к трём видео и голосу, затем полноценной приёмке монтажа. Авторские рабочие черновики в этот опыт не входят.

Владелец следующего опыта — инженер медиа по назначению оркестратора; сборщик проверяет результат. Новый обзор всего рынка не нужен. Условие пересмотра интеграции — результат этого опыта либо изменение версии приложения/инструмента. См. [решение владельца](../decisions/0002-capcut-and-motion.md) и [моушен-направление](../../motion/README.md).
