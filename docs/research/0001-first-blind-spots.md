# 0001 — слепые зоны первого проверяемого пакета

Дата проверки источников: 29.09.2026. Владелец вопроса: оракул знаний. Адресат: главный оркестратор.

## Вывод

Для этапа 1 полезнее доказать происхождение нескольких кадров и их положение на **исходной** шкале времени, чем сразу выбирать ASR или автоматический монтаж. Главные риски: потеря времени при VFR и seek; ложное покрытие материала выборкой или детектором сцен; скрытая зависимость первого среза от среды распознавания речи. Это рекомендации по изученным источникам, а не результат запуска на видео автора.

## Три риска и варианты

### 1. Время исходника теряется при извлечении

**Свидетельство.** FFmpeg предупреждает: входной `-ss` обычно ищет ближайшую предыдущую точку доступа; `-fps_mode cfr` дублирует или удаляет кадры; даже `-copyts` не гарантирует совпадения выходных меток с входными из-за режима частоты и muxer. Фильтр `fps` также дублирует/удаляет кадры. `ffprobe -show_frames` даёт сведения по декодированным кадрам. [F1], [F2], [F3]

| Вариант | Точность для VFR и смещённого старта | Цена и проверяемость |
|---|---|---|
| `номер кадра / средний fps` или время выходного файла | Ненадёжен: подменяет неравные интервалы средней величиной | Просто записать, трудно заметить дрейф |
| Исходные PTS + `time_base` и явная связь производного кадра с исходным | Сохраняет проверяемую координату; пустой/испорченный PTS остаётся явной ошибкой | Нужно хранить метаданные и сверять кадры |

**Рекомендация.** Выбрать второе для контракта пакета. Сохранять идентификатор исходника, индекс потока, исходные PTS/`time_base`, фактически выбранный кадр и параметры извлечения. Запрошенное время выборки хранить отдельно от фактического. Не считать `-copyts` универсальным исправлением. Неизвестно: какие контейнеры и разрывы меток будут у материала автора. При отсутствии надёжного PTS остановить заявление о точном времени и исследовать конкретный файл.

### 2. «Найденный переход» создаёт ложную уверенность в покрытии

**Свидетельство.** PySceneDetect `ContentDetector` сравнивает соседние кадры по изменению цвета/яркости; `AdaptiveDetector` использует локальное среднее, чтобы уменьшить ложные срабатывания при движении камеры. В актуальной документации 0.7.1 для VFR точные вычисления опираются на PTS и `time_base`; номер кадра при VFR может быть приблизительным. Это алгоритмы границ, а не доказательство содержания сцены. [S1], [S2]

| Вариант | Немая сцена | Короткое событие между пробами | Цена и смысл результата |
|---|---|---|---|
| Равномерная ограниченная выборка кадров | Может показать её при попадании пробы | Может пропустить | Дешёвое и честно измеримое покрытие |
| Границы PySceneDetect как дополнительные точки | Может добавить кадр около резкого перехода | Не гарантирует событие внутри непрерывной сцены | Потребует настройки порога; даёт переход, не смысл |
| Тишина/движение как основание удалить интервалы | Удалит часть немых моментов | Удаление необратимо для анализа | auto-editor применяет пороги громкости/движения; `0` по умолчанию режется [A1] |

**Рекомендация.** На этапе 1 брать ограниченную выборку по исходной шкале и честно указывать непокрытые промежутки. Границы сцен оценивать позднее как дополнение; исходник не резать. Идея auto-editor — наглядно показать предлагаемые к исключению интервалы — полезна для будущего интерфейса, но правило «тишина = мусор» переносить нельзя. Неизвестно: частота и длительность важных событий у автора. Если важный эпизод систематически попадает между пробами, вернуться к плотности или адаптивной выборке на конкретном типе материала.

### 3. Речь может незаметно стать обязательной частью первого шага

**Свидетельство.** faster-whisper даёт режим CPU `int8` и GPU `float16`/`int8_float16`; Python ≥3.9. Системная установка FFmpeg ему не обязательна, потому что PyAV поставляет библиотеки FFmpeg. Для текущего GPU-пути README требует NVIDIA cuBLAS для CUDA 12 и cuDNN 9; на Windows предлагается отдельное размещение библиотек в `PATH`. По имени модели веса скачиваются с Hugging Face. Сегменты ленивы: работа начинается при их переборе. [W1] Эти условия не подтверждают работоспособность на данной машине и не отменяют отдельную проверку лицензии весов.

| Вариант | Соответствие этапу 1 | Зависимость от среды | Проверяемость |
|---|---|---|---|
| Не требовать ASR для пакета | Полное: речь относится к этапу 2 | Нет модели и GPU | Этап 1 проверяется без транскрипта |
| Позже: локальный CPU `int8` | Заменяемый речевой слой | Время и RAM надо измерить | Можно отдельно проверить коротким аудио |
| Позже: Windows/NVIDIA GPU | Возможное ускорение, если оно нужно | CUDA/cuDNN, драйвер, версия CTranslate2 и объём VRAM | Нужен явный тест среды, не молчаливый fallback |

**Рекомендация.** Сейчас выбрать первый вариант. Для этапа 2 начинать с явного локального адаптера и протокола «доступен / ошибка / отключён», затем измерить CPU и только при нужде GPU. Не обещать скорость из README: его бенчмарки проведены на указанном авторами железе, не на машине владельца. [W1] В этой записке не проверены совместимость ASR с установленным железом, качество русской речи автора, доступность модели без сети и лицензия выбранных весов.

## Малый эксперимент для этапа 1

После завершения основания создать **один синтетический VFR-ролик 8–12 секунд**: известные PTS с неравными интервалами, смещённый старт, два резких перехода и заметный немой интервал. Исходник и ожидаемые признаки зафиксировать отдельно от производных. Провести `ffprobe -show_frames`, получить небольшую выборку кадров, записать для каждого запрос и фактический исходный PTS. Сверить фактические PTS со списком декодированных кадров и видимые метки с ожидаемыми; проверить hash исходника до/после и явно назвать интервалы без пробы. Критерий: ни один кадр не получает время только из `номер / средний fps`; неизвестное время помечено ошибкой; исходник не меняется. Затем отдельно проверить один материал автора, если он его выберет. Реальный тест пока **не выполнен**.

## Риск процесса: агентская каша и лишняя документация

Семь ролей полезны как ответственность, но семь обязательных ответов на каждый маленький шаг создадут противоречивые задания и расход без нового свидетельства. Для этого исследования был один владелец и один адресат; спор о PTS передавать инженеру медиа/архитектору только с конкретным контрпримером. Оркестратор хранит решение и приёмку, интегратор изменяет Git. Исследование не становится постоянным надзором.

Ещё один документ не исправит неверную временную метку. Эту записку пересматривать только после нового файла, сбоя эксперимента или изменения проверенных API/лицензий. Исходные ссылки и один критерий эксперимента достаточны; подробный обзор всех VLM, монтажных программ и будущих интерфейсов сейчас увеличит шум.

**Направление 4i7:** лево/право — варианты выше оценены по общим критериям; назад — остановить утверждение о точном времени при расхождении PTS; вперёд — передать оркестратору один эксперимент с проверкой исходной шкалы. Следующий адресат: оркестратор, затем назначенные им инженер медиа и архитектор контракта. Условие пересмотра: результат синтетического и выбранного автором материала противоречит допущению о достаточности исходных PTS и ограниченной выборки.
